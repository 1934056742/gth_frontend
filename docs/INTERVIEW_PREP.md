# 面试复习冲刺计划（分片上传 + AI/RAG）

> 目标：3 天内从「项目不熟」到「能扛住 30 分钟深挖」。
> 原则：**不背代码，背「为什么」**。面试官要的是判断力，不是默写。

---

## 0. 先明确策略：挑 2 个模块讲深，其余一句话带过

项目里可讲的东西很多（RBAC、JWT 双 token、任务看板、文件分类…），但**面试时间有限，深挖只会发生在你主动讲深的地方**。

推荐主打（这两个最有技术含量）：

| 模块 | 为什么值得主打 | 配套材料 |
| --- | --- | --- |
| **大文件分片上传（秒传 / 断点续传）** | 有算法（SHA-256 / 并发池）、有边界（暂停竞态、并发合并）、有安全（分片目录归属） | `MODULE_GUIDE.md`、`UPLOAD_MODULE.md`、`INTERVIEW_QA.md` |
| **AI 答疑 + 知识库 RAG** | 新兴热点，能讲算法（BM25）、协议（SSE）、工程（防幻觉 / 降级 / 脱敏） | `AI_MODULE_GUIDE.md` |

其余模块准备**一句话版本**即可（下文第四节有现成话术）。

## 1. Day 1：把「链路」跑通并画出来（约 2.5 小时）

### 1.1 亲手跑一遍（40 分钟）

```powershell
# 后端
cd backend
npm install
npx prisma migrate dev        # 或 prisma db push
npm run dev                   # http://localhost:xxxx

# 前端
cd frontend
npm install
npm run dev
```

然后**以用户身份操作一遍**，边操作边在纸上画：

1. 上传一个 100MB+ 的文件 → 观察「计算指纹 → 校验 → 上传中」三个状态；
2. 上传到一半点「暂停」，再点「继续」→ 看分片数是否从断点继续（不是从 0）；
3. 同一个文件再传一次到另一个任务 → 观察是否显示「秒传」；
4. 打开 AI 对话，问一个**知识库里有的问题** → 看回答底部是否出现「参考来源」；
5. 问一个**知识库里没有的问题** → 看模型是老实说不知道，还是编。

> 这一步的价值：面试时你说「我实测过 100MB 文件，暂停后从第 12/20 片继续」比说「支持断点续传」可信十倍。

### 1.2 画两张图（40 分钟，白纸手画）

**图 1：分片上传时序**（只画主干）

```
前端                    后端
 │ ① 算 SHA-256（Web Worker，流式读）
 │ ② POST /upload/check {fileHash,...}
 │ ─────────────────────────────►  查 files.json / 分片目录
 │ ◄──── {exists:true}   → 秒传，结束
 │ ◄──── {exists:false, uploadedChunks:[0,1,2]}
 │ ③ 并发 3 个 worker 传剩余分片
 │ ──── POST /upload/chunk (index=3) ─►  落盘 chunks/{hash}/3
 │ ◄──── {merged:false}
 │ ...最后一片
 │ ──── POST /upload/chunk (最后一片) ─►  检测 received.size == totalChunks
 │                                       → 流式合并到临时文件 → rename
 │ ◄──── {merged:true, url}
```

**图 2：AI 问答链路**

## 2. Day 2：把两个难点「讲到能画公式」（约 2 小时）

### 2.1 分片上传的三个杀手锏问题（背思路，不背代码）

| 追问 | 你的答案骨架 |
| --- | --- |
| 为什么要算 SHA-256，10GB 要多久？ | 内容指纹才能秒传；10GB 约 25~40s（浏览器 SHA-256 约 300MB/s）；优化：Web Worker 不卡 UI + 流式增量（读 2MB 算一次）+ 只算头部+尾部+大小做「快速指纹」（简历上别说已经做了，说「下一步方案」） |
| 并发数为什么是 3？ | HTTP/1.1 同域 6 连接，留余量给其他请求；可调 1~6；真正瓶颈常在服务端磁盘 IO |
| 暂停时正在飞的分片怎么办？ | 先置 `running=false` 让 worker 循环失效，再 `abort()`；`AbortError` 静默吞掉，不能弹「网络异常」（这个 bug 我真修过） |

**加分细节（真实修过的 bug，讲出来很值钱）**：
> 「暂停后点继续，结果弹出文件选择框」——根因是用 `errorMsg` 字段当「是否占位任务」的标志位，而 `errorMsg` 会残留。修法是改用显式 `needsFile` 标记（占位任务的 File 是空壳）。**教训：状态不要用文案推断，要用显式枚举/标志位。**

### 2.2 RAG 的四个杀手锏问题

| 追问 | 你的答案骨架 |
| --- | --- |
| 为什么不用向量检索？ | DeepSeek 无 Embedding 接口；文档术语固定，关键词召回够用；零成本、可解释。局限：口语化提问会漏召回 → 下一步混合检索 |
| BM25 公式？ | 现场写 `Σ IDF·tf(k1+1)/(tf + k1(1-b+b·len/avgLen))`，解释 k1 饱和、b 长度归一化、IDF 稀有词权高 |
| 怎么防幻觉？ | prompt 强约束「只依据资料，没有就说不知道」+ 编号来源让你能追溯 + 分数阈值 0.5 过滤无关片段 |
| 中文怎么分词？ | 二元切分 + 英文整词；不用 jieba 因为要本地编译、部署麻烦 |

### 2.3 演练「三分钟讲模块」（30 分钟）

对每个模块，用手机录音讲 3 分钟，要求包含：**背景 → 难点 → 我的方案 → 数字 → 踩坑**。
听回放，删掉所有「大概、应该、好像是」。

## 3. Day 3：模拟面试 + 补漏（约 2 小时）

### 3.1 自问自答（60 分钟）

- 用 `INTERVIEW_QA.md`（30 题上传）+ `AI_MODULE_GUIDE.md` 第 7 节（12 题 AI）过一遍，**每题开口说**，卡壳的记下来；
- 特别练「我不知道」的正确说法：
  > 「这块我没做到那一步。我的理解是 X，如果要实现我会先 Y 验证再 Z 落地，但没实测过，不敢说结论。」

### 3.2 打开代码随机抽查（30 分钟）

让朋友（或自己随机）指一个函数名，你要能立刻说出它做什么、为什么这么写。重点抽查：

- `frontend/src/utils/uploadManager.ts`：`startTask`、`pauseTask`、`resumeByFile`
- `frontend/src/utils/hash.ts` / `sha256.ts`：增量哈希
- `backend/src/upload.ts`：`mergeChunksToFile`、`claimChunkDir`
- `backend/src/knowledge.ts`：`tokenize`、`scoreChunks`、`splitIntoChunks`
- `backend/src/ai.ts`：`openSse`、`callModel`、`retrieveKnowledge`
- `frontend/src/api/ai.ts`：`splitSseEvents`

### 3.3 准备「反问」和「不足」（30 分钟）

主动暴露不足是加分项，但**必须配整改方案**：

> 「这个项目我自己清楚短板：① 上传元数据存 JSON 文件而不是数据库（量大时要迁 Prisma + 对象存储）；② 检索只有 BM25，没做向量；③ 没有 CI，测试是手动跑的。如果继续做，优先级是 ①对象存储+分片直传 ②混合检索 ③CI。」

## 4. 其余模块的一句话话术（被问到才展开）

| 模块 | 一句话 |
| --- | --- |
| 鉴权 | JWT 双 token：access 30 分钟 + refresh 7 天（库里只存 refresh 的哈希，`@@unique` 一条一人），前端 401 自动静默续期 |
| RBAC | 角色 `admin` / `member`，后端每个路由都校验，前端 `permission.ts` 只做菜单隐藏（**前端权限不是安全边界**） |
| 任务看板 | 状态 `todo/doing/done` 流转驱动，分配后自动变「进行中」，完成时写 `completedPerson` 快照 |
| 文件权限 | 按 `ownerId` 隔离；挂在同一任务下的文件对任务参与者可见（`canListFileWithoutTask`），删除仍只能删自己的 |
| 测试 | 后端 `node:test` 195 个用例全绿，前端 Vitest 覆盖上传引擎/SSE 解析/权限判断 |
